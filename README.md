## 一、程序说明

**用途**：临时锁定键盘鼠标（防猫踩键鼠），屏幕照常播放；可快捷解锁。

**位置**：源码 `D:\Project\my-project\cat-lock\`；计划任务实际运行 `D:\App\GongJu\小猫锁\CatLock\CatLock.exe`（部署副本，两份 exe 保持一致）。

**编译命令**（.NET Framework 自带 csc，编译前必须先结束 CatLock.exe 进程）：
```
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe ^
  /out:"D:\App\GongJu\小猫锁\CatLock\CatLock.exe" ^
  /win32icon:"D:\Project\my-project\cat-lock\assets\catlock.ico" ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll ^
  "D:\App\GongJu\小猫锁\CatLock\CatLock.cs"
```
建议：先编译到临时目录，再以 `--selftest` 冒烟一次（见下），确认 `hooks installed ok` 后再替换正式版。

**配置文件 `catlock.ini`**（0=关，1=开）：
```
hotkey=1          # Ctrl+Alt+L 锁/解锁切换
button=1          # 屏幕上方按钮解锁
hint=1            # 锁定后提示说明卡片
quithotkey=0/1    # Ctrl+Alt+Q 退出
autostart=0/1     # 开机自动启动（优先"计划任务"以管理员静默启动；见第三章）
idlelock=0/1      # 无操作自动上锁（系统级闲置判定）
idleminutes=6     # 闲置分钟数（1-600）
```
注：手工改 ini 把 hotkey/button 全关时，程序会强制启用快捷键（防呆）；`Ctrl+Alt+U` 仅作解锁用，不会上锁。

**启动参数**：
- 无参数：手动启动 → 3 秒后自动锁定（倒计时期间点按钮可取消）
- `--autostart`：开机自启（静默，不锁定；由计划任务调用）
- `--elevated`：以管理员重启用（静默，不锁定；带互斥体等待，替换旧实例）
- `--selftest`：调试用。**独立互斥体**（可与正式实例并存）、**不碰注册表/计划任务**、**永不锁定**、钩子照装、日志照记；也不注册全局热键备用通道。

**核心机制（v1.4 更新）**：
- 全局低级钩子：`WH_KEYBOARD_LL` + `WH_MOUSE_LL`（安装于 UI 线程，消息泵 = `Application.Run`）
- 锁定期间：吞 **键盘按下** 和 **鼠标点击/滚轮**；放行 键盘抬起、鼠标移动、鼠标按键抬起（按系统按键状态机安全放行）、按钮矩形内点击
- **钩子回调只做判定与吞/放行**，UI/日志一律延迟执行（日志=内存队列，300ms 泵批量落盘，写盘已加串行化锁）
- 解锁方式：① `Ctrl+Alt+L` 切换 ② `Ctrl+Alt+U` 备用解锁 ③ 上方按钮（连点两下，或右键后 8 秒内左键）④ 30 分钟保底自动解锁
  - **v1.3 新增 RegisterHotKey 备用通道**：钩子被系统摘掉/装不上时，`Ctrl+Alt+U`（及 Q）仍能经系统热键到达。注意本机 `Ctrl+Alt+L` 已被其他程序占用（错误码 1409，见第二章 #2），故备用以 U 为主；钩子活着时会吞掉这些组合键，系统热键不会重复触发（带去抖 120ms）。
- 多屏：**解锁按钮每块屏幕顶部居中各一个**；提示卡跟随鼠标所在屏（与该屏按钮重叠时自动下移）。（v1.3 关闭旧"仅主屏"边界）
- **DPI 感知方式（v1.4 改）= 每显示器 DPI v2**（`SetProcessDpiAwarenessContext(-4)`）：进程不再被 Windows 做 DPI 虚拟化，`Screen.Bounds` / 窗口矩形 / 鼠标钩子坐标始终是同一套物理像素。拿不到时退回旧的 `SetProcessDPIAware()`，此时靠下面的顶部解锁区兜底。
- **显示器/缩放自检（v1.4 新增）**：每 2 秒比对一次 `Screen.AllScreens` 指纹（设备名+位置+尺寸+主屏标记），与上次不一致就重新算缩放、重建/重排按钮并按当前状态重新显示。**不再只依赖 `WM_DISPLAYCHANGE`**（远程连接时它可能收不到，或收到时屏幕信息还没刷新）。同时处理 `WM_DPICHANGED`。
- **屏幕顶部解锁区（v1.4 新增）**：锁定期间，鼠标按下若落在任一屏幕顶部一条区域（高度 ≈ 按钮高 + 80px，至少 150px，**不限 x**）内，即使没点在按钮窗口上，也按"点了解锁按钮"处理（同一套连点两下 / 右键+左键状态机）。用于兜住远程桌面/缩放导致鼠标坐标整体偏移、点不到小按钮的情况。日志记为 `unlock zone hit: ...`。
- Windows 锁屏联动（WTS）：锁屏自动解除小猫锁；锁屏期间不触发闲置锁；解锁后重置 且 **若实例是在 Windows 已锁屏期间被闲置锁锁上的，用户解锁 Windows 时也自动解除小猫锁**
- **闲置判定 = 系统级 `GetLastInputInfo`**；睡眠唤醒后 30 秒、会话解锁后 10 秒抑制闲置锁
- **运行时自愈**：钩子 180 秒收不到事件但系统活跃 → 重装；未锁定时 60 分钟预防性重装；重装采用"先装新、成功后再摘旧"，任何情况都不会出现无钩子窗口；重装失败记错误码（锁定中钩子失效 → 强制解锁 fail-open）
- **钩子回调异常兜底**：异常进日志；锁定中异常保守吞掉（fail-closed）；同一 pump 周期内连续 ≥10 次异常 → 自动解锁（防钩子持续故障把用户锁死）
- **看门狗**：UI 线程卡死且处于锁定超过 90 秒 → 强制退出（保底解锁，fail-open；退出前会冲掉待写日志）
- 计时统一走**单调时钟**（Stopwatch），锁定时长/闲置抑制/连点窗口不受系统改时间影响
- UI：每屏顶部红/绿状态按钮、鼠标所在屏左下角圆角提示卡（点击穿透）、托盘图标（小猫锁图形：绿=未锁/红=已锁/灰=已暂停，图标按系统小图标尺寸矢量绘制，tooltip 显示剩余保底分钟；右键菜单：立即锁定/暂停运行（或恢复运行）/设置/以管理员身份重启(未提权时)/退出）
- **暂停运行（v1.5 新增）**：托盘右键 →「暂停运行」后，闲置自动锁、`Ctrl+Alt+L` 快捷键锁定、托盘「立即锁定」全部停用；菜单变为「恢复运行」，图标转灰。仅当前运行周期有效，重启程序后自动恢复运行。
- UI 尺寸按系统 DPI 缩放（本机 150%：按钮 260×48 逻辑 → 390×72 物理）

## 二、v1.3 改进清单（2026-10-07）

> 来源：逐段代码复核 + 多轮真机验证（冷启动 / --selftest / 双屏按钮几何 / 设置窗口布局 / 按钮连点解锁注入）。

**多屏与视觉：**
1. 解锁按钮从"仅主屏一个"改为**每屏各一个**（`Screen.AllScreens` 动态增删，显示器热插拔/分辨率变化自动重建）。实测 2560×1440 主屏 + 1440×2560 副屏：两屏按钮均正确居中 + 缩放。
2. 提示卡跟随**鼠标所在屏**；与该屏上部按钮重叠时自动下移（窄屏不再互相遮挡）。
3. **DPI 感知缩放**：所有 UI 尺寸/间距/圆角/提示卡绘制坐标按系统 DPI 换算（本机 150%），修复高 DPI 下按钮/开关偏小、文字被裁剪的问题。托盘图标改用 `SystemInformation.SmallIconSize`（高 DPI 不再发虚）。

**可靠性 / 防"锁死"：**
4. **RegisterHotKey 备用通道**（旧"已知边界 #5"）：低频钩子被摘掉时的第二条解锁/退出路径；去抖 120ms 防双通道重复触发。
5. 钩子重装**先装新、成功后再摘旧**，杜绝"重装瞬间无钩子"；重装失败记录 `HOOK_REINSTALL FAILED` 及错误码；**锁定中钩子失效 → 强制解锁（fail-open）**。
6. 钩子回调**异常兜底**：锁定中异常保守吞掉（fail-closed，不再漏拦输入）；一夜周内连续异常 → 自动解锁（fail-open）。
7. 计时改**单调时钟**（Stopwatch / `NowMs()`）：`DateTime.Now` 被系统改时间/授时跳变不影响 30 分钟保底、8 秒右键窗口、1.2 秒连点窗口等判定。
8. Windows 解锁联动补齐：实例在 Windows 已锁屏期间被闲置锁锁上（收不到锁屏事件）时，用户解锁 Windows 会顺带解除小猫锁——回来后不会迎面被锁。
9. 看门狗退出前冲日志；日志落盘加锁，杜绝与 UI 线程并发写打断。

**日志 / 设置 / 其余：**
10. 设置窗口新增**状态行**（当前锁否 / 权限 / 版本）与**"查看日志"按钮**；布局按 DPI 缩放、开关自动调宽。
11. 托盘 tooltip 显示"已锁定（保底 N 分钟后自动解锁）"；`start:` 行增加 `dpiAware / scale / screens=`。
12. 计划任务存在性检测增强：退出码之外再判输出是否含 `\CatLock`（权限受限误报时兜底）。
13. 解锁反馈兜底：即使关闭了屏幕按钮，解锁时也短暂显示绿色确认（2.5 秒）。
14. 钩子重装/注册热键/显示器变化等新增日志；`click ... PASS/SWALLOW` 逐点击日志保留（问题排查需要）。

**注意（真机发现）**：本机有多屏（2560×1440 主 + 1440×2560 副），且屏幕当前常处于 Windows 锁屏状态；锁屏桌面上 `SendInput` 注入会被 UIPI 拦截——**只有在解锁的桌面上才能做交互式热键/点击的端到端验证**（无人值守时用下面的 PostMessage 法验证按钮路径）。

### v1.4 修复（2026-10-19）—— 远程连接后"双击屏幕按钮解锁"失效

**现象**：通过远程连接（RDP/远程控制）使用本机时，点屏幕上方按钮双击解不开，只能用 `Ctrl+Alt+L`。

**取证**（catlock.log，v1.3 运行期）：

```
2026-10-19 09:38:34  LOCK (闲置超时(6分钟))
2026-10-19 09:48:34  click msg=513 at 905,44  -> SWALLOW   ← 连点 4 组全被吞
2026-10-19 09:48:39  hotkey Ctrl+Alt+L matched, locked=True via hook → UNLOCK   ← 最后靠快捷键
```
对比本地正常时：`click msg=513 at 1421,56 -> PASS` → `UNLOCK: 已解锁（连点两下）`。

**根因（两条）**：
1. **程序错过显示器变化**。v1.3 只在收到 `WM_DISPLAYCHANGE` 时才重排按钮；远程连接时该广播可能收不到，或收到时 `Screen.AllScreens` 还没刷新。实测 v1.3 实例一直以为屏幕是 2560×1440@150%（按钮算出来在 x=1085、宽 390），而当时实际显示是 **1920×1080@100%**（按钮该在 x=830、宽 260）。用户按"看到的位置"点（x≈905 / 1450+），全部落在真实按钮矩形之外 → 被吞。
2. **坐标空间不统一**。历史日志里出现过 `display changed -> ... 1707x960 ...`（DPI 虚拟化后的逻辑尺寸）——系统级 DPI 感知进程在会话 DPI 变化后会被虚拟化，而低级鼠标钩子给的是**物理**坐标，两套坐标对不上时命中判定必然失败。

**修复**：见第一章新增的三条机制——改每显示器 DPI v2（消除虚拟化）、加 2 秒显示器自检（不再依赖单次广播、自动纠偏）、加顶部解锁区兜底（坐标整体偏移也能解锁）。另外每次 LOCK / 显示器变化都会把按钮真实矩形写进日志（`lock ui: ... btn=...`），下次再出问题一眼就能对上。

**部署后实测**（本机当前正由 RDP 接入，1920×1080@100%）：
```
start: ver=1.4 ... pmv2=True scale=1 screens=\\.\DISPLAY1[P]=1920x1080@0,0 ...
lock ui: scale=1 screens=\\.\DISPLAY1[P]=1920x1080@0,0 btn=\\.\DISPLAY1=830,12 260x48 vis=1
```
按钮位置/尺寸已正确跟随当前显示器；连续观察无反复重排（自检不抖）。

### v1.5 新增（2026-11-07）—— 托盘「暂停运行 / 恢复运行」

**需求**：在托盘右键菜单增加暂停/恢复，暂停后停用所有锁定入口。

**实现**：
- 托盘菜单新增 `暂停运行` / `恢复运行`，`trayPauseItem.Text` 随状态切换；暂停时「立即锁定」置灰。
- 新增 `paused` 运行时状态；`SetPaused()` 负责切换、取消待执行的启动倒计时、刷新托盘图标（灰）与 tooltip。
- `LockNow()` 入口统一加暂停守卫：闲置自动锁、`Ctrl+Alt+L` 快捷键、启动倒计时、托盘立即锁定全部不会再上锁；闲置判断额外加 `!paused`，避免暂停期间每 300ms 重复尝试。
- 暂停只影响“上锁”；`Ctrl+Alt+U` 解锁、`Ctrl+Alt+Q` 退出不受影响。暂停状态**不写配置**，重启程序后恢复运行（避免用户忘记恢复导致保护长期关闭）。
- 日志新增 `PAUSE (...)` / `RESUME (...)` / `lock skipped (paused): ...`。

## 三、开机自启与提权（v1.1 起不变）

**问题**：非管理员运行时，Windows UIPI 导致"管理员程序窗口里热键无效、锁定不拦截、活动不计数"。

**当前方案（两部分）：**
1. **单次启动即管理员**：CatLock.exe 带"以管理员身份运行"兼容标志（`HKCU\...\AppCompatFlags\Layers`），且本机 UAC=提权不弹窗 → 任何方式启动都静默以管理员运行。
2. **开机自启 = 计划任务**：任务名 `CatLock`，登录时（只使用交互方式）运行 `CatLock.exe --autostart`，权限最高（/RL HIGHEST）。
   查看：`schtasks /query /tn CatLock`。程序内"开机自动启动"开关提权时自动创建/删除该任务；未提权时回退注册表方式并记日志。
   注意：`--selftest` 实例**跳过**自启管理，不会碰计划任务/注册表。

## 四、日志与排障

- 日志：`catlock.log`（UTF-8）。写入=内存队列+300ms 批量落盘（进程被强杀可能丢最后 <1 秒的内容）。
- **排障第一看 `start:` 行**：含 `ver=elevated=dpiAware=pmv2=scale=screens=`。
- 常见行释义：
  - `hooks installed ok` / `hooks reinstalled (...)`：钩子正常/自愈完成
  - `HOOK REINSTALL FAILED (...) k=... errK=... m=... errM=...`：重装失败（保留旧钩子）
  - `LOCK (...)` / `UNLOCK: ...`：锁定来源与解锁原因（快捷键/闲置超时/启动倒计时/托盘菜单/保底/锁屏联动/钩子失效兜底）
  - `PAUSE (...)` / `RESUME (...)`：托盘暂停/恢复运行（v1.5）
  - `lock skipped (paused): ...`：暂停期间被拦下的上锁请求（v1.5）
  - `lock ui: scale=... screens=... btn=\\.\DISPLAYn=x,y 宽x高 vis=...`：**每次锁定时按钮的真实屏幕矩形**（v1.4 新增，排查"点不到"先看这行）
  - `display changed -> scale=... screens=... locked=... btn=...`：显示器/缩放变化后的重排（含按钮新位置）
  - `click msg=... at x,y -> PASS/SWALLOW [zone] btn=...`：锁定期间的每次点击判定；`PASS`=落在按钮上，`[zone]`=落在顶部解锁区兜底，`SWALLOW`=两者都不是
  - `unlock zone hit: <屏> top+N (zoneH=...) btn=Left/Right at x,y`：顶部解锁区命中（v1.4 新增）
  - `hotkey Ctrl+Alt+L matched, locked=... via hook|RegisterHotKey`：热键收到（没这行=按键没到程序）
  - `hotkeys backup: Ctrl+Alt+L=True/False(err=1409)...`：备用热键注册结果（1409=已被其他程序占用）
  - `countdown cancelled (btn)`：倒计时被按钮取消
  - `windows session LOCKED/UNLOCKED`：Windows 锁屏联动事件
  - `WATCHDOG: ...`：UI 卡死强制退出保险生效（罕见）
  - `autostart: ...`：自启管理动作
- 若"锁不上/解不开"复现：先看日志——
  - `click ... -> SWALLOW` 且坐标明显不在 `btn=` 矩形里 → 鼠标坐标与窗口矩形对不上（远程/缩放），v1.4 起会走 `[zone]` 兜底；若连 `[zone]` 都没命中，说明点得太靠下
  - `display changed` 长时间不出现但分辨率确实变了 → 说明自检也没捕捉到，看 `screens=` 是否与服务端实际分辨率不符
  - 有 `hotkey ... matched` 但状态没变 → 看该时刻是否管理员窗口焦点/安全桌面
  - 完全无记录 → 程序没收到按键（安全桌面/UAC 弹窗中不经过钩子，属设计边界）
- 手动调试：`CatLock.exe --selftest`（独立互斥体，可与正式实例并存，绝不锁定，不碰注册表/计划任务，不注册全局热键）。

## 五、已知边界（有意不修 / 暂不修）

1. **安全桌面**（UAC 提权弹窗、登录界面、Windows 锁屏）上的输入不经过任何用户层钩子——设计限制，无法锁，也不会被锁死。
2. **Ctrl+Alt+Del** 永远有效（SAS 不经钩子）——最终兜底：任务管理器可结束 CatLock.exe；或按"锁定"，回来后小猫锁会自动解除。
3. 锁定期间托盘菜单不可达（所有点击被吞，只有按钮矩形例外）——设计如此。
4. RDP/快速用户切换等会话事件目前只记日志，未做深度联动（如远程接管时自动放行）；但**远程导致的显示器/缩放变化已被 v1.4 自检处理**（按钮会自己挪到正确位置）。
5. ~~未实现 RegisterHotKey 备用通道~~ → **已实现**；但本机 `Ctrl+Alt+L` 已被其他程序占用（err 1409），备用通道以 `Ctrl+Alt+U`/`Ctrl+Alt+Q` 为主（若以后想换组合键，改 `HKID_*` 与 `ApplyHotkeys` 里的 vk）。
6. ~~锁定按钮仅主屏~~ → **已改为每屏一个**。
7. 触摸屏/精密触控板的多指手势（切换桌面、任务视图等）可能不走低级鼠标钩子，防猫效果有限——属 Windows 行为边界。
8. **顶部解锁区是有意放宽的**：锁定期间任意屏幕顶部那一条（高 ~150px）双击即解锁，不再要求精确命中按钮。代价是"在屏幕最上方双击"也会解锁（此时点击本来就被吞掉，不会漏给下面的程序）。若嫌太宽松，改 `InUnlockZone()` 里的 `zoneH`（可把 x 也限制在按钮附近，但那样远程缩放场景又会失效）。

## 七、给下一位维护者

- 改代码前：先读第三章（提权与自启）、第四章（日志字段）；理解两次事故：v1.2（2026-10-05"能锁不能解"：锁定吞掉修饰键按下后物理键态恒抬起，必须以 `(locked && ctrlDown/altDown)` 叠加判定）、v1.4（2026-10-19 远程后点不到按钮：不要假设 `WM_DISPLAYCHANGE` 一定到、也不要假设进程看到的坐标与鼠标钩子的坐标同一套；**凡是用屏幕坐标做判定的地方都要考虑 DPI/远程**）。
- 部署流程：备份 → 编译到临时目录 → `--selftest` 冒烟 → 停进程（提权则 `taskkill /F /IM CatLock.exe`，非提权可注入 Ctrl+Alt+Q）→ 替换 → `schtasks /Run /TN CatLock` → 看日志 start 行。
- 回滚：`CatLock_v1.4_backup.exe` 覆盖（再往前可回 `CatLock_v1.2_backup.exe`）+ 任务保留（旧版不认计划任务，会尝试 Run 项自启——记得在设置里重设一次自启开关）。
- 真机交互测试法：
  - 注入热键/点击用 PowerShell `SendKeys::SendWait`；**屏幕被 Windows 锁屏时注入会被 UIPI 拒绝**，需先解锁桌面，或用 `Start-Process taskkill -Verb RunAs` 停进程。
  - 无人值守时验证"按钮解锁"：把源码里 `MUTEX_NAME` 换成独立名编译一个测试实例（temp 目录 + 独立 ini）跑起来，它 3 秒后自锁；用 `PostMessage(WM_LBUTTONDOWN/UP)` 对按钮窗口发连点，看日志 `UNLOCK`。测试实例勿用正式互斥体。
- 测试版务必用独立的互斥体名 + 独立目录运行，避免碰到正式版的注册表/计划任务。
- 本机屏幕常处于锁屏：很多"锁不上/解不开"的复现要先确认桌面是否已解锁。
- 远程连接（RDP/远程控制）会同时改变**分辨率**和**缩放比例**，并可能让 `WM_DISPLAYCHANGE` 收不到。排查"按钮点不到"时：比对日志里的 `btn=` 矩形与用户实际点击坐标（`click ... at x,y`），两者对不上就是坐标空间/布局过期问题。
